# 데이터 안내 — 직원·휴가·급여를 관리하려면 무엇이 필요한가

> ⚠️ **교육용 가상 자료입니다.** 예시로 나오는 (가상) 한빛상사(주)와 서지환 부장은 지어낸 것입니다.
>
> 이 문서는 **인사·총무 담당자가 "우리 회사 인사 자료를 어떻게 정리해야 하나"를 잡을 때** 보는 설명서입니다.
> 프로그램을 만들 줄 몰라도 읽을 수 있게 썼습니다. 엑셀로 관리하는 경우에도 그대로 적용됩니다.

> 📁 **실제 자료 파일**: [`data/가상_인사총무.json`](data/가상_인사총무.json)
> 이 문서에서 설명하는 내용이 **그대로 들어 있는 데이터 파일**입니다.
> 직원 10건 · 휴가신청 6건 · 급여 12건. 메모장으로도 열리고, 항목 이름이 전부 한글입니다.
> 자세한 내용은 **9장**을 보세요.

## 0. 한 문장 요약

> **사번 하나만 제대로 붙여두면, 나머지는 전부 거기에 꿰어 달 수 있습니다.**

## 1. 큰 그림 — 자료는 세 종류뿐입니다

인사 자료가 복잡해 보이는 건 종류가 많아서가 아니라, **성격이 다른 걸 섞어놨기 때문**입니다.
먼저 세 칸으로 갈라놓으면 훨씬 단순해집니다.

| 종류 | 성격 | 예시 | 몇 줄인가 |
|---|---|---|---|
| **① 기본 자료** | 잘 안 바뀜. 사람마다 딱 하나 | 사번, 이름, 입사일, 소속, 직급 | 한 사람당 **1줄** |
| **② 사건 기록** | 일이 생길 때마다 쌓임. 지우지 않음 | 인사발령, 출퇴근, 휴가 신청 | 한 사람당 **여러 줄** |
| **③ 계산 결과** | 저장하지 않음. 필요할 때 매번 계산 | 근속연수, 연차 잔여, 급여, 세금 | 저장 안 함 |

**③번이 핵심입니다.** 연차 잔여일수를 엑셀 칸에 적어두는 순간, 그 숫자는 반드시 틀어집니다.
휴가를 하나 승인할 때마다 손으로 고쳐야 하는데, 사람은 반드시 빼먹기 때문입니다.

> **원칙: 계산할 수 있는 값은 저장하지 않는다.**
> 입사일만 저장해두면 근속연수는 언제든 계산됩니다. 반대로 근속연수를 저장하면 매년 전부 고쳐야 합니다.

## 2. 직원 자료 — 무엇을 갖고, 무엇을 안 갖나

### 2-1. 꼭 있어야 하는 것

| 항목 | 예시 | 왜 필요한가 |
|---|---|---|
| **사번** | `HB-0002` | **모든 자료를 꿰는 열쇠.** 이게 없으면 나머지가 다 무너집니다 |
| 이름 | 서지환 | 사람이 알아보기 위한 것. **열쇠로 쓰면 안 됩니다** (아래 2-3 참고) |
| 소속 | 경영지원본부 / 경영지원팀 | 조직도, 결재선, 부서별 집계 |
| 직급 · 직책 | 부장 · 팀장 | 기본급, 직책수당이 여기서 나옴 |
| **입사일** | 2014-05-12 | **연차 발생일수와 근속수당의 출발점.** 가장 중요한 날짜 |
| 재직상태 | 재직 / 휴직 / 퇴사 | 급여 대상인지, 4대보험 신고 대상인지 결정 |
| 퇴사일 | (비어 있음) | 퇴사자만. 경력증명서·퇴직금 계산의 근거 |
| 휴직 사유 | (비어 있음) | 휴직자만. 급여가 왜 0원인지 설명하는 칸 |
| **공제대상가족 수** | 3명 | **소득세를 정하는 값.** 본인·배우자를 각각 1명으로 셈 |
| **8~20세 자녀 수** | 1명 | 자녀세액공제 금액이 여기서 갈림 |
| 연락처 | 내선 1002, 사내메일 | 업무 연락용 |

### 2-2. 갖지 않기로 한 것 — 그리고 그 이유

| 안 갖는 것 | 이유 |
|---|---|
| 주민등록번호 | 4대보험 신고·연말정산 때만 필요합니다. 평소 명부에 두면 유출 위험만 커집니다 |
| 계좌번호 | 급여 이체 시스템에만 있으면 됩니다. 인사 명부에 있을 이유가 없습니다 |
| 집 주소 상세 | 통근버스·경조사 발송처럼 실제 쓸 일이 있을 때만 |
| 가족 이름·생년월일 | **가족 "수"만 있으면 세금 계산이 됩니다.** 이름까지 필요하지 않습니다 |

> **판단 기준은 하나입니다 — "이 칸을 지금 무슨 업무에 쓰는가?"**
> 답이 바로 안 나오면 갖지 마세요. 갖는 순간 지켜야 할 의무가 생깁니다.
>
> 우리 앱이 **가족 "수"는 갖고 가족 "이름"은 안 갖는 것**이 이 원칙의 실제 사례입니다.

### 2-3. 왜 이름이 아니라 사번인가

이름을 열쇠로 쓰면 세 가지 상황에서 반드시 깨집니다.

| 상황 | 무슨 일이 벌어지나 |
|---|---|
| **동명이인** | 김민수가 두 명이면 누구 급여인지 알 수 없음 |
| **개명** | 이름이 바뀌는 순간 과거 자료와 연결이 끊김 |
| **퇴사 후 재입사** | 같은 이름인데 다른 근속 기간. 연차·퇴직금이 뒤섞임 |

사번은 **한 번 주면 절대 바꾸지 않고, 재사용하지도 않습니다.**
퇴사자 `HB-0010`의 사번을 신입에게 다시 주면, 퇴사자의 옛 자료가 신입에게 달라붙습니다.

## 3. 휴가 자료 — 신청 한 건이 한 줄

### 3-1. 휴가 신청서에 필요한 칸

| 항목 | 예시 | 왜 필요한가 |
|---|---|---|
| 신청번호 | 4 | 이 신청서를 가리키는 번호 |
| **사번** | `HB-0002` | ← **직원 자료와 연결되는 고리** |
| 휴가 종류 | 반차(오후) | 연차 / 반차 / 병가 / 경조사… 종류마다 차감 여부가 다름 |
| 시작일 · 종료일 | 2026-08-20 ~ 2026-08-20 | |
| **일수** | 0.5일 | **주말·공휴일을 뺀 실제 근무일.** 반차는 0.5일 |
| 사유 | 개인 사유 | |
| **결재 상태** | 대기 / 승인 / 반려 | **승인된 것만 연차에서 차감됩니다** |
| 결재자 | 팀장 | 누가 승인했는지 |

### 3-2. 연차 잔여는 "저장"이 아니라 "계산"입니다

```
   발생일수  −  사용일수  =  잔여일수
      20        3.5         16.5
       │          │
       │          └── 승인된 휴가 신청서를 전부 더한 값
       └───────────── 입사일과 회사 규칙으로 계산한 값
```

서지환 부장(HB-0002)의 실제 계산:

| 단계 | 값 | 근거 |
|---|---|---|
| 발생 | 20일 | 2014-05-12 입사 → 근속 12년 → 기본 15일 + 가산 5일 |
| 사용 | 3.5일 | 이전 사용분 3일 + 2026-08-20 반차 0.5일 |
| **잔여** | **16.5일** | 20 − 3.5 |

**휴가를 하나 승인하면 이 숫자가 저절로 바뀝니다.** 어디에도 손으로 고칠 곳이 없습니다.
그게 "계산해서 쓴다"의 뜻입니다.

### 3-3. 휴가 종류마다 다른 점

| 종류 | 연차에서 차감? | 급여는? |
|---|---|---|
| 연차 | **차감** | 유급 (급여 그대로) |
| 반차 | **0.5일 차감** | 유급 |
| 병가 | 회사 규정에 따라 다름 | 회사 규정에 따라 다름 |
| 경조사 | 보통 차감 안 함 | 유급 |
| 무급휴가 | 차감 안 함 | **급여에서 공제** |

> 회사마다 다릅니다. **취업규칙에 뭐라고 쓰여 있는지 먼저 확인**하고 나서 시스템에 넣으세요.

## 4. 급여 자료 — 대부분은 "가져다 쓰는" 값입니다

급여 자료에서 **새로 입력하는 건 거의 없습니다.** 대부분 다른 데서 끌어옵니다.

### 4-1. 어디서 오는가

| 항목 | 예시(서지환, 2026년 9월) | 어디서 오나 |
|---|---|---|
| 기본급 | 5,000,000원 | 직원 자료의 **직급** |
| 직책수당 | 250,000원 | 직원 자료의 **직책**(팀장) |
| 근속수당 | 300,000원 | 직원 자료의 **입사일** → 근속 12년 |
| 식대(비과세) | 200,000원 | 회사 규정 (정액) |
| 연장근로수당 | 143,530원 | **근태 기록**의 연장시간 4시간 |
| 결근공제 | −166,660원 | **근태 기록**의 결근 1일 |
| **지급 총액** | **5,726,870원** | 위 항목을 더하고 뺀 값 |

→ 새로 입력한 값은 **하나도 없습니다.** 전부 직원 자료와 근태 기록에서 나옵니다.

### 4-2. 공제는 법이 정합니다

| 항목 | 금액 | 기준 |
|---|---|---|
| **과세대상액** | **5,526,870원** | 지급총액 − **비과세 식대 200,000원** |
| 국민연금 | 262,480원 | 과세대상액 × 4.75% |
| 건강보험 | 198,690원 | 과세대상액 × 3.595% |
| 장기요양 | 26,100원 | 건강보험료 × 13.14% |
| 고용보험 | 49,740원 | 과세대상액 × 0.9% |
| **소득세** | **284,100원** | **간이세액표에서 조회** (아래 4-3) |
| 지방소득세 | 28,410원 | 소득세 × 10% |
| **공제 총액** | **849,520원** | |
| **실지급액** | **4,877,350원** | 5,726,870 − 849,520 |

> ⚠️ **가장 흔한 실수: 비과세 식대를 안 빼는 것.**
> 200,000원을 안 빼면 공제 7개가 **전부** 틀립니다. 한 칸이 아니라 전부입니다.

### 4-3. 소득세는 계산이 아니라 "표에서 찾는 것"

소득세는 국세청이 만든 **근로소득 간이세액표**에서 찾습니다. 두 가지만 있으면 됩니다.

```
   가로축:  과세대상액 5,526,870원   →  5,520~5,540천원 구간
   세로축:  공제대상가족 3명
                    ↓
             표에서 찾은 금액  304,930원
             − 자녀세액공제(1명)  20,830원
             ────────────────────────
             소득세            284,100원
```

**같은 급여라도 가족 수가 다르면 세금이 크게 달라집니다.**

| 서지환 부장의 조건 | 소득세 | 실지급액 |
|---|---|---|
| 가족 3명 · 자녀 1명 (실제) | 284,100원 | 4,877,350원 |
| 가족 1명 · 자녀 0명이라면 | **408,400원** | 4,740,620원 |

급여는 1원도 안 바뀌었는데 **매달 12만 원 차이**입니다.
그래서 **공제대상가족 수는 반드시 직원 자료에 있어야 하는 칸**입니다.

## 5. 같은 직원의 자료를 어떻게 연결하나

### 5-1. 그림 한 장

```
                    ┌───────────────────────────┐
                    │       사원명부            │
                    │   HB-0002  서지환         │  ← 한 사람당 1줄
                    │   경영지원팀 · 부장 · 팀장 │
                    │   입사 2014-05-12         │
                    │   가족 3명 · 자녀 1명     │
                    └─────────────┬─────────────┘
                                  │
                            사번  HB-0002
                                  │
        ┌───────────┬─────────────┼─────────────┬────────────┐
        ▼           ▼             ▼             ▼            ▼
   ┌─────────┐ ┌─────────┐  ┌──────────┐  ┌─────────┐  ┌─────────┐
   │인사발령 │ │근태기록 │  │휴가신청  │  │자산대장 │  │회의실   │
   │HB-0002  │ │HB-0002  │  │HB-0002   │  │사용자=  │  │예약자=  │
   │         │ │         │  │          │  │HB-0002  │  │HB-0002  │
   │입사 1건 │ │하루 1줄 │  │신청 1건  │  │노트북   │  │주간회의 │
   │         │ │(41줄)   │  │= 1줄     │  │모니터   │  │         │
   └─────────┘ └────┬────┘  └────┬─────┘  └─────────┘  └─────────┘
                    │            │
                    └─────┬──────┘
                          ▼
                   ┌─────────────┐
                   │   급여계산  │   ← 저장 안 함. 볼 때마다 계산
                   │  실지급     │
                   │  4,877,350  │
                   └─────────────┘
```

**모든 표에 `사번` 칸이 하나씩 들어 있습니다. 그게 전부입니다.**
표를 아무리 많이 만들어도, 사번만 정확히 적혀 있으면 한 사람의 자료를 언제든 모을 수 있습니다.

### 5-2. 줄 수가 다른 이유

| 표 | 서지환의 줄 수 | 왜 |
|---|---|---|
| 사원명부 | **1줄** | 사람은 하나뿐 |
| 인사발령 | 1줄 | 입사 발령 1건 (승진하면 늘어남) |
| 근태기록 | **41줄** | 하루에 한 줄. 실적 30줄(8/1~9/11) + 예정 11줄(9/14~9/30) |
| 휴가신청 | 1줄 | 신청할 때마다 늘어남 |
| 자산대장 | 2줄 | 노트북 + 모니터 |

> 사원명부만 "한 사람당 한 줄"이고, **나머지는 전부 여러 줄**입니다.
> 그래서 사원명부를 **기준 표**라고 부릅니다.

### 5-2-1. 근태에는 "실적"과 "예정"이 섞여 있습니다

같은 근태 표인데 성격이 다른 두 구간이 들어 있습니다.

| 구간 | 기간 | 내용 | 급여에 쓰나 |
|---|---|---|---|
| **실적** | 8/1 ~ 9/11 | 출퇴근 시각·연장·지각·결근이 **기록되어 있음** | **쓴다** |
| **예정** | 9/14 ~ 9/30 | 출퇴근 기록 **없음**. 승인된 휴가와 공휴일만 | **안 쓴다** |

기준일(2026-09-14) 이후는 **아직 일어나지 않은 날**입니다.
출퇴근을 지어내서 급여를 계산하면 그게 더 이상합니다. 그래서 급여는 실적 구간만 씁니다.

> 실무에서도 급여 마감은 "언제까지의 근태로 계산할지"를 먼저 정하고 시작합니다.

### 5-3. 자료가 흐르는 순서

```
  ① 인사발령  →  ② 사원명부  →  ③ 근태·휴가  →  ④ 급여  →  ⑤ 4대보험
   (사건 발생)     (현재 상태)     (매일 쌓임)     (월 1회)    (신고)
```

**왼쪽이 틀리면 오른쪽은 전부 틀립니다.**

실제 예시 — 승진 발령을 빠뜨리면:

```
  ① 승진 발령 누락
       ↓
  ② 명부에 아직 "과장"   ← 이미 여기서 틀림
       ↓
  ④ 기본급이 과장 기준으로 계산  → 급여 미달 지급
       ↓
  ⑤ 4대보험 신고액도 미달  → 나중에 소급 정산
```

한 칸을 빠뜨렸을 뿐인데 뒤에서 세 가지가 터집니다.
**그래서 발령부터 제대로 넣는 것이 인사 업무의 시작입니다.**

## 6. 엑셀로 관리한다면

프로그램 없이 엑셀만 쓰는 경우에도 원칙은 똑같습니다.

| 하세요 | 하지 마세요 |
|---|---|
| 시트를 **표 하나에 하나씩** 나누기 (사원명부 / 근태 / 휴가 / 급여) | 시트 하나에 전부 몰아넣기 |
| 모든 시트 **A열에 사번** 두기 | 이름으로 `VLOOKUP` 하기 |
| 잔여 연차는 **수식으로** 계산 | 잔여 연차를 손으로 입력 |
| 날짜는 `2026-08-20` 형식 통일 | `26.8.20`, `8/20`, `8월20일` 섞어 쓰기 |
| 한 칸에 값 하나 | `경영지원팀 부장` 처럼 한 칸에 두 정보 |
| 파일명에 **날짜와 버전** 넣기 | `사원명부_최종_진짜최종.xlsx` |

> **가장 흔한 사고**: 같은 엑셀 파일을 여러 명이 각자 고쳐서, 어느 게 맞는지 아무도 모르게 되는 것.
> 파일 하나를 **원본으로 정하고, 고치는 사람을 한 명으로 제한**하세요.

## 9. 실제 자료 파일 — `data/가상_인사총무.json`

이 문서의 내용을 그대로 담은 **가상 데이터 파일**입니다.
메모장·엑셀·브라우저 무엇으로든 열 수 있고, **항목 이름이 전부 한글**이라 프로그램을 몰라도 읽힙니다.

### 9-1. 무엇이 들어 있나

| 표 | 건수 | 구성 | 성격 |
|---|---|---|---|
| `직원` | **10건** | 재직 8 / 휴직 1 / 퇴사 1 | ① 기본 자료 — 한 사람당 1줄 |
| `휴가신청` | **6건** | 승인 3 / 대기 2 / 반려 1 | ② 사건 기록 — 신청 1건당 1줄 |
| `급여` | **12건** | 6명 × 2개월(2026-08, 2026-09) | ② 사건 기록 — 사람 × 월 조합당 1줄 |
| `참고_연차계산_저장대상_아님` | 6건 | — | ③ **계산 결과. 원래는 저장하지 않음** |

앞에 `_` 가 붙은 것(`_안내`, `_코드표`, `_계산규칙`, `_연결방법`)은 자료가 아니라 **설명서**입니다.
파일 하나만 받아도 무슨 자료인지 알 수 있게 같이 넣었습니다.

### 9-2. 마지막 칸이 일부러 이상하게 들어간 이유

`참고_연차계산_저장대상_아님` 이라는 긴 이름이 붙은 칸이 있습니다.
연차 발생·사용·잔여가 들어 있는데, **이건 원래 저장하면 안 되는 값**입니다(1장 ③번).

일부러 이름에 그렇게 써 놓았습니다.
"이 값들은 입사일과 휴가 기록만 있으면 언제든 다시 계산된다"는 걸 파일 자체가 말하도록 한 것입니다.

### 9-3. 급여는 열쇠가 두 개입니다

직원과 휴가는 **사번** 하나로 한 줄을 찾을 수 있습니다. 그런데 급여는 안 됩니다.

```
   사번 HB-0002  →  급여에 2줄  (2026-08 한 줄, 2026-09 한 줄)

   사번 HB-0002 + 귀속월 2026-09  →  딱 한 줄
```

> **"사람 × 기간" 으로 쌓이는 자료는 열쇠가 두 개**입니다. 근태(사번 + 날짜)도 마찬가지입니다.
> 엑셀에서 `VLOOKUP` 이 자꾸 엉뚱한 줄을 잡아오는 이유가 대개 이것입니다.

파일에서는 `급여번호`(예: `PAY-2026-09-0002`)를 따로 붙여 한 줄을 바로 가리킬 수 있게 해 두었습니다.

### 9-4. 서지환 부장(HB-0002) 따라가 보기

파일 안에서 한 사람을 실제로 꿰어 보면 이렇게 나옵니다.

| 어디에 | 몇 줄 | 무슨 내용 |
|---|---|---|
| `직원` | 1줄 | 경영지원팀 부장·팀장, 2014-05-12 입사, 가족 3명·자녀 1명 |
| `휴가신청` | 1줄 | `LV-2026-003` · 2026-08-20 반차(오후) 0.5일 · 승인 |
| `급여` | 2줄 | `PAY-2026-08-0002`, `PAY-2026-09-0002` |

그리고 급여 한 줄 안에는 **소득세가 어떻게 나왔는지까지** 들어 있습니다.

```
   과세대상액 5,526,870원
        │
        ├─ 간이세액표_구간_천원 : "5520~5540"    ← 표의 어느 칸을 봤는지
        ├─ 공제대상가족수        : 3             ← 세로축
        ├─ 표조회금액            : 304,930원     ← 표에서 찾은 값
        └─ 자녀세액공제          : 20,830원      ← 빼는 값
                                 ─────────────
                     소득세      : 284,100원
```

> **숫자만 있는 자료는 나중에 아무도 검증하지 못합니다.**
> "어떤 표의 어느 칸을 봤는가"를 같이 남겨야, 6개월 뒤에 다시 확인할 수 있습니다.

### 9-5. 잔여를 넘겨 신청한 건이 하나 들어 있습니다

`휴가신청` 6건 중 한 건에 `"잔여초과여부": true` 가 붙어 있습니다.

| 신청번호 | 사번 | 내용 | 잔여 | 신청 |
|---|---|---|---|---|
| `LV-2026-005` | HB-0008 나선호 | 2026-10-05~06 연차 | **1.6일** | **2일** |

나선호 사원은 2025-07-01 입사라 연차가 **비례 부여(7.6일)** 밖에 안 됩니다.
이미 6일을 써서 잔여가 1.6일인데 2일을 신청했습니다.

**결재 전에 잔여를 확인해야 하는 이유**가 이 한 줄에 들어 있습니다.
그냥 승인하면 나중에 무급 처리나 정산이 따라붙습니다.

### 9-6. 이 파일로 할 수 있는 것

- **엑셀로 옮기기** — 6장의 원칙대로 시트 3개(직원 / 휴가신청 / 급여)로 나눠 붙여보기
- **연결 연습** — 사번으로 세 표를 이어 "서지환의 9월 자료 전부"를 뽑아보기
- **검산** — 앱 화면(급여대장·연차 관리)과 파일의 숫자가 같은지 대조하기
- **실습 문제 만들기** — 예: "잔여를 넘겨 신청한 사람은 누구인가?"

> 파일의 모든 숫자는 **앱의 계산 로직으로 직접 뽑아낸 것**이라, 앱 화면과 1원 단위까지 일치합니다.

## 10. 한 장 요약

```
  ① 사번을 붙인다. 절대 바꾸지 않는다.
  ② 모든 표에 사번 칸을 둔다. 그걸로 전부 연결된다.
  ③ 계산할 수 있는 값은 저장하지 않는다.
  ④ 지금 쓸 데가 없는 개인정보는 갖지 않는다.
  ⑤ 발령 → 명부 → 근태 → 급여 → 신고. 앞이 틀리면 뒤는 전부 틀린다.
```
