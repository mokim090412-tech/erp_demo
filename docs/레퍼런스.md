# 레퍼런스 — 상용 HR 제품에서 가져올 것 3가지

> 이 문서는 **(가상) 한빛상사 인사·총무 교육용 가상 앱**을 더 낫게 만들기 위한 조사 기록입니다.
> 앱 자체는 교육용 가상 자료이고, 여기 정리한 것은 **실제 제품들의 공개 문서**입니다.
>
> 조사일: 2026-09-14 · 조사 대상: flex(한국) / Frappe HR(오픈소스) / Odoo(오픈소스 ERP)
> 조사 방법: 각 제품의 **공식 문서·제품 소개 페이지만** 읽음. 블로그 후기나 3자 리뷰는 제외.

---

## 고른 기준

우리 앱은 이미 15개 화면이 있습니다. 그래서 "없는 기능"을 무작정 더 담는 대신,
**교육 효과가 큰데 지금 비어 있는 자리**를 기준으로 골랐습니다.

1. 우리 앱의 핵심 메시지(`인사발령 → 근태 → 연차 → 급여`)를 **더 선명하게 만드는가**
2. 인사담당자가 **실무에서 실제로 틀리는 지점**인가
3. 10명짜리 가상 회사에서 **한 화면 안에 보여줄 수 있는가**

## ① Odoo — Work Entries: "충돌을 다 풀기 전에는 급여를 만들 수 없다"

**출처**
- [Work entries — Odoo 18.0 documentation](https://www.odoo.com/documentation/18.0/applications/hr/payroll/work_entries.html)
- [Payroll — Odoo 18.0 documentation](https://www.odoo.com/documentation/18.0/applications/hr/payroll.html)

**Odoo가 하는 일**

Odoo는 근태·휴가·공휴일·교육을 전부 **work entry** 라는 한 종류의 레코드로 바꿉니다.
work entry는 "직원 타임시트 위의 개별 기록"이고, 유형(Attendance / Sick Time Off / Training /
Public Holiday / Paid Time Off 등)마다 **급여 코드와 색깔**이 붙습니다.
이 기록들은 Planning·Attendances·Time Off 앱에서 **자동으로 생성**됩니다.

핵심은 **충돌(conflict) 처리**입니다.

- 휴가 신청이 아직 승인 안 됐거나 기록에 오류가 있으면 그 날짜에 **주황색 삼각형**이 뜹니다.
- 대시보드는 기본 필터가 `Conflicting` 이라서, **문제 있는 것만** 먼저 보여줍니다.
- 달력 화면에서 바로 `Approve Time Off` / `Refuse Time Off` 를 눌러 해결하거나,
  원본 휴가 신청으로 넘어가 상세를 보고 처리합니다.
- 그리고 문서에 이렇게 못 박혀 있습니다:
  > "Conflicts that span the current pay period being processed **must be resolved before payslips can be generated**"
  (처리 중인 급여 기간에 걸친 충돌은 **급여명세서를 만들기 전에 반드시 해결되어야 한다**)

**우리 앱의 현재 상태**

근태가 급여로 넘어가긴 합니다 — 연장시간은 연장수당으로, 결근일수는 결근공제로.
그런데 **조용히** 넘어갑니다. 중간에 확인하는 단계가 없습니다.
지금은 교육생이 급여대장 숫자를 그냥 믿게 됩니다. 대기 중인 휴가가 9건 남아 있어도 급여는 그냥 계산됩니다.

**왜 참고할 가치가 있나**

우리 앱의 마무리 멘트가 "앞 칸이 틀리면 뒤 칸은 전부 틀린다"입니다.
그런데 지금은 그걸 **말로만** 합니다. Odoo의 방식은 그걸 **화면이 강제**합니다.
"급여를 만들려면 먼저 근태를 확정하라"는 규칙 하나가, 설명 열 마디보다 강합니다.

또 이건 실무에서 실제로 사고가 나는 지점입니다.
미승인 휴가를 남겨둔 채 급여를 마감하면 → 그 사람은 결근 처리되어 급여가 깎이고 → 뒤늦게 소급 정산이 붙습니다.

**우리 앱에 넣는다면 (구체안)**

급여대장 위에 **「급여 마감 전 점검」** 이라는 작은 단계를 하나 끼웁니다.

| 점검 항목 | 우리 데이터로 판정하는 법 |
|---|---|
| 귀속월에 걸친 **미결재 휴가** | `S.leaves` 중 `status === '대기'` 이고 기간이 해당 월과 겹치는 건 |
| **잔여 초과 승인** 건 | 승인된 연차 합계 > 발생일수 인 사원 |
| **결근인데 휴가 신청이 없는 날** | 근태 `결근` 인데 그 날짜에 휴가 레코드가 없음 |
| 퇴사자 명의 **미회수 자산** | 이미 자산 대장에 있는 경고를 여기로 끌어옴 |

- 문제가 있으면 급여대장 상단에 **주황 배너 + 건수**, 각 항목은 클릭하면 해당 화면으로 이동
- `[급여 확정]` 버튼은 **문제가 0건일 때만** 활성화
- 확정 후에는 대장이 잠기고, 되돌리려면 `[확정 취소]`

교육생이 "확정 버튼이 왜 안 눌리지?" 하는 순간, 이 앱이 가르치려던 걸 스스로 깨닫습니다.

## ② Frappe HR — Leave Type: "연차 규칙은 코드가 아니라 설정이다"

**출처**
- [Leave Type — Frappe HR Documentation](https://docs.frappe.io/hr/leave-type)
- [Leaves — Frappe HR Documentation](https://docs.frappe.io/hr/leaves)
- [Leave Policy Assignment — Frappe HR Documentation](https://docs.frappe.io/hr/leave-policy-assignment)
- [Leave Management — Frappe HR](https://frappe.io/hr/leave-management)

**Frappe HR이 하는 일**

휴가를 6개 문서로 쪼개고, 이 순서로 흘려보냅니다.

```
Leave Type(휴가 종류·규칙)
  → Leave Policy(정책: 종류별 며칠)
    → Leave Policy Assignment(누구에게 적용)
      → Leave Allocation(실제 배분)
        → Leave Application(신청·승인)
          → Leave Ledger Entry(원장: 잔여의 근거)
```

그리고 **Leave Type 화면 하나에 규칙이 전부 체크박스로 들어 있습니다.**

| 옵션 | 뜻 |
|---|---|
| `Is Carry Forward` | 남은 휴가를 다음 기간으로 이월 |
| `Is Earned Leave` (+ Frequency, Rounding) | 근속에 따라 **주기적으로 적립** · 단수 처리 방식까지 선택 |
| `Allow Negative Balance` | 잔여가 없어도 신청·승인 허용 |
| `Maximum Consecutive Leaves Allowed` | 연속 사용 한도. **초과분은 무급휴가로 처리** |
| `Include holidays within leaves as leaves` | 휴가 기간 중 공휴일을 휴가 일수에 **포함할지** |
| `Allow Leave Application After (Working Days)` | 입사 후 며칠 지나야 신청 가능 |
| `Is Leave Without Pay` / `Is Partially Paid Leave` | 무급 / 부분 유급 (급여에서 공제·부분 지급) |
| `Is Compensatory` | 초과·휴일근무 보상휴가 |
| `Allow Encashment` (+ Non-Encashable Leaves, Earning Component) | 미사용분 **현금 환급**, 급여 항목으로 연결 |

**우리 앱의 현재 상태**

연차 규칙 3개가 JavaScript에 하드코딩되어 있습니다.
(2026년 입사 → 월 1일 / 2025년 입사 → 비례 / 그 이전 → 15일 + 가산)

화면에 규칙을 글로 써 두긴 했지만, **바꿀 수는 없습니다.**
교육생이 "우리 회사는 입사일 기준인데요?" 하고 물으면 보여줄 게 없습니다.

**왜 참고할 가치가 있나**

인사담당자가 연차에서 헤매는 진짜 이유는 계산이 어려워서가 아닙니다.
**법이 정한 최소선 위에 회사 취업규칙이 얹혀 있고, 그 조합이 회사마다 다르기 때문**입니다.

Frappe HR의 Leave Type 화면은 그 사실을 그대로 드러냅니다.
"이건 법이 정한 게 아니라 우리가 정한 것"과 "이건 바꿀 수 없는 것"이 한 화면에서 갈립니다.
교육에서 이보다 좋은 교보재가 없습니다.

특히 `Allow Negative Balance` 는 우리 앱과 정확히 겹칩니다.
지금 우리는 잔여를 넘겨 승인하려 하면 `confirm()` 경고창을 띄우는데,
Frappe는 그걸 **회사가 미리 정하는 정책**으로 올려놨습니다. 이쪽이 실무에 가깝습니다.

**우리 앱에 넣는다면 (구체안)**

연차 관리 화면에 **「휴가 정책 설정」** 탭을 추가합니다. 전부 토글·드롭다운으로.

| 설정 | 선택지 | 바꿨을 때 일어나는 일 |
|---|---|---|
| 연차 기준 | **회계연도(1/1) ↔ 입사일** | 10명 전원의 발생일수가 즉시 다시 계산됨 |
| 미사용분 이월 | 허용 / 소멸 | 잔여 계산식이 바뀜 |
| 잔여 초과 신청 | 차단 / 경고만 / 허용 | 휴가 결재 화면의 ⚠ 동작이 바뀜 |
| 휴가 중 공휴일 | 일수에 포함 / 제외 | 추석 낀 휴가 신청의 일수가 달라짐 |
| 반차 사용 단위 | 0.5일 / 시간 단위 | 신청 화면의 입력 방식이 바뀜 |

- **설정을 바꾸면 10명의 연차표가 눈앞에서 통째로 다시 그려지는 것**이 이 화면의 목적입니다.
- 기본값은 지금 규칙 그대로 두고, `[기본값으로]` 버튼으로 언제든 복귀.
- 실습 과제 추가: *"연차 기준을 입사일 기준으로 바꾸면 조민석의 발생일수는 며칠이 됩니까?"*

## ③ flex — 연차 사용 촉진: 한국 인사담당자만 하는 절차

**출처**
- [flex – 근태 관리 (제품 소개)](https://flex.team/about/features/time-tracking)
- [flex 기능 — flex 헬프센터](https://guide.flex.team/ko/collections/11068081-flex-%EA%B8%B0%EB%8A%A5)
- [flex – 워크플로우 (제품 소개)](https://flex.team/about/features/workflow)

> ※ 앞의 두 제품과 달리 flex 자료는 **제품 소개 페이지**라 마케팅 문구가 섞여 있습니다.
> 그래서 기능의 **존재 여부**만 근거로 쓰고, 세부 동작은 우리가 법령을 보고 설계해야 합니다.

**flex가 하는 일**

flex는 연차를 "부여 → 소멸"로 끝내지 않고 **촉진**까지 자동화합니다.

> "회사 정책에 맞게 연차 부여 소멸 설정만 하면 더 이상 신경쓰지 않아도 돼요."
>
> "스마트 연차 촉진 … 한 번 설정해두면 법에 맞게 자동으로 돌아가는 연차 촉진.
> **노무수령거부 통지 기록까지** 챙겨드리니 안심하세요."
>
> "법정필수휴가를 포함하여 … 휴가 별로 **승인, 사용 단위, 증빙자료 제출** 등의 옵션을 설정할 수 있어요."

담당자 화면 쪽도 참고할 만합니다.

> "근태 대시보드와 인사이트를 통해 출퇴근 시간, 초과근무, 미입력, 코어타임 준수, 지각 관리까지 손쉽게 확인"
>
> "**조직도를 통해 각 조직별 초과근무와 휴가 사용 현황**도 쉽게 파악할 수 있습니다."

**우리 앱의 현재 상태**

**연차 사용 촉진이 아예 없습니다.**
우리 앱은 연차를 "발생 − 사용 = 잔여"까지만 다룹니다. 잔여가 많이 남은 사람을 보여주긴 하지만,
그래서 담당자가 **무엇을 해야 하는지**는 말해주지 않습니다.

조직도도 지금은 이름·직급만 나오는 정적인 트리입니다.

**왜 참고할 가치가 있나**

연차 사용 촉진은 **근로기준법 제61조**에 절차와 기한이 정해진, 한국 인사담당자의 고유 업무입니다.
절차를 제대로 밟아야 미사용 연차 수당 지급 의무가 면제되고, 한 단계만 놓쳐도 효력이 없습니다.

그런데 이건 Odoo·Frappe HR 같은 해외 제품에는 **아예 없는 개념**입니다.
한국 인사담당자 교육용 앱이라면 이 자리가 비어 있으면 안 됩니다. 우리 앱의 가장 큰 공백입니다.

그리고 이건 우리 앱과 궁합이 좋습니다.
이미 10명의 **발생·사용·잔여**를 다 계산하고 있으니, 촉진 대상자 판정에 필요한 재료가 전부 있습니다.

**우리 앱에 넣는다면 (구체안)**

연차 관리 화면에 **「연차 사용 촉진」** 탭을 추가합니다.

1. **촉진 일정 타임라인** — 회계연도 기준 기한을 달력 위에 표시
   - 1차 촉진: 기간 만료 6개월 전 기준 → 사용 시기 지정·통보 요청
   - 근로자 사용 계획 회신
   - 2차 촉진: 기간 만료 2개월 전 → 회사가 사용 시기 지정·통보
   - 미사용 시 → 노무수령 거부 통지
   - 각 단계에 **우리 기준일(2026-09-14)이 어디쯤인지** 표시

2. **촉진 대상자 목록** — 잔여일수 기준 자동 추출
   - 현재 데이터로는 서지환(16.5일) · 신우재(16일) · 한도경(15.5일)이 상위
   - 각 행에 `[1차 촉진 통보]` `[사용 계획 접수]` `[2차 촉진 통보]` `[노무수령 거부]` 단계 버튼
   - 누른 기록이 **문서 대장에 자동 등록** → 기존 화면과 연결됨

3. **실습 과제 추가**
   - *"잔여 연차 15일 이상인 사원 전원에게 1차 촉진을 통보하고, 문서 대장에 기록이 남았는지 확인하세요."*

> **주의** — 실제 구현 전에 근로기준법 제61조 조문으로 기한을 반드시 재확인해야 합니다.
> 이 문서의 단계 구분은 flex 소개 페이지에서 "그런 절차가 있다"는 것만 확인한 것이고,
> **정확한 일수는 아직 법령으로 검증하지 않았습니다.**

곁다리로 flex의 조직도 아이디어도 싸게 가져올 수 있습니다.
우리 조직도의 각 팀 옆에 이미 인원수·평균 근속이 있으니, **팀별 연차 소진율**을 한 칸 더 붙이면 됩니다.

## 우선순위 제안

| 순위 | 항목 | 손이 얼마나 가나 | 교육 효과 |
|---|---|---|---|
| 1 | ① 급여 마감 전 점검 (Odoo) | **작음** — 기존 데이터만 조합, 새 화면 1개 | **큼** — 앱의 핵심 메시지를 화면이 강제 |
| 2 | ③ 연차 사용 촉진 (flex) | 중간 — 새 탭 + 문서 대장 연동 + 법령 확인 필요 | **큼** — 한국 실무 공백을 메움 |
| 3 | ② 휴가 정책 설정 (Frappe HR) | 큼 — 연차 계산 로직을 설정 기반으로 재작성 | 큼 — 다만 앞 두 개보다 난이도가 높음 |

①번부터 하는 걸 권합니다. 지금 있는 데이터만 다시 엮으면 되고, 새 화면 하나로 앱 전체의 메시지가 단단해집니다.

## 참고 시 주의할 점

- **가져오는 것은 개념과 업무 흐름이지, 코드나 화면 디자인이 아닙니다.**
  Frappe HR은 GPLv3, Odoo Community는 LGPLv3입니다. 소스를 그대로 옮겨 쓰면 라이선스 의무가 따라옵니다.
  flex는 상용 서비스라 화면을 베끼면 안 됩니다. **"이런 업무 단계가 있다"만 배우고, 구현은 우리가 새로 합니다.**
- flex 자료는 **제품 소개 페이지**라 마케팅 표현이 섞여 있습니다. 기능의 존재 근거로만 쓰고,
  법정 절차의 기한·요건은 **반드시 법령 원문으로 다시 확인**해야 합니다.
- Odoo 문서는 버전마다 내용이 다릅니다. 이 문서는 **18.0** 기준이고, 19.0도 공개되어 있습니다.
